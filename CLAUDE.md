# Оценка звонков администраторов — «Варикоза нет»

Сервис для сети клиник лазерной хирургии вен «Варикоза нет» (первая клиника — Владивосток). Записи звонков
администраторов приходят из Mango Office (автоматически по API или загрузкой файлов), расшифровываются на
компьютере клиники, ИИ оценивает каждый звонок по регламенту клиники (чек-лист) и даёт балл и обратную связь.

История решений, результаты проверок, ограничения и планы развития — в `docs/PROJECT_MEMORY.md`. Прочитай его
перед новой задачей.

## Работа с пользователем

- **Всегда общайся по-русски.** Пользователь — владелец клиники, не программист: объясняй без жаргона.
- Порядок работы, который он задал: сначала предложить варианты, обсудить, потом разрабатывать.
- Приоритеты пользователя: максимально бюджетно; телефония Mango Office; сейчас одна клиника (2 администратора),
  дальше — сеть до ~70 клиник; настройки должны быть гибкими, чтобы клиники настраивали всё сами.
- Персональные данные пользователь считает не критичными (никуда не уходят, кроме текста расшифровки в ИИ).

## Код и git

- Python 3.12, FastAPI + Jinja2 (без сборки фронтенда), SQLAlchemy 2 + SQLite (WAL), фоновые потоки.
- Тесты: `python -m pytest -q` (около 40 с, все должны проходить). Зависимости для тестов — `requirements-dev.txt`.
- Коммиты — по-русски, понятным языком, что изменилось для пользователя. Без названий моделей ИИ в коммитах.
- PR не создавать без просьбы пользователя.
- Каждый исправленный баг закрепляй регрессионным тестом и проверяй, что тест падает на предыдущей версии кода
  (git worktree с прошлым коммитом).
- Запуск у пользователя: Windows, `start.bat` (создаёт `.venv`, `.env` из `.env.example`, запускает `python -m app`).

## Правила, которые нельзя ломать

- **Изоляция клиник.** Любой запрос к данным фильтруется по `ctx.clinic_id`; руководитель видит только свою клинику.
- **Обработка звонка без долгих транзакций.** Расшифровка и запросы к ИИ идут вне транзакции; запись результата —
  короткой транзакцией через `_claim` (обновление только если статус не изменился). «Свой» звонок узнаётся по
  `created_at` (класс `_Run`). `requeue()` всегда пишет статус (`flag_modified`).
- **История оценок.** Пункты и сценарии не удаляются, а отключаются (`active=False`); `CriterionResult` хранит
  снимок текста пункта. Коды пунктов (`CODE_RE`, верхний регистр) и ключи сценариев (`KEY_RE`) уникальны в клинике.
- **Чек-лист другой клиники** (`foreign`): совпавший код с другим текстом — новый пункт; поиск по тексту сначала
  в своём разделе, затем среди пунктов, которые иначе отключились бы; удалённые пункты не оживлять, если в разделе
  есть действующий с тем же текстом. Сведения о клинике для ИИ (`ai_context`) при копировании не переносятся.
- **Безопасность форм.** Никаких данных внутри inline-JavaScript: подтверждения только через `data-confirm`.
  Сообщения после действий — только через `redirect(url, msg=…, err=…)`. Cookie входа для уже вошедшего
  пользователя выдаётся с `sv=ctx.session_version`.
- **Excel.** Строки пишутся через `_append()` — текст на «=» не становится формулой.
- **Mango.** Лимиты: `stats/request` не чаще раза в 2 с, `stats/result` раз в 5 с, паузы при 429/503; недоступная
  запись (`MangoRecordingError`) пропускается, остальные загружаются. Время в API — обычный Unix (UTC).
- **Числа из форм** — через `to_int()` (только ASCII-цифры, не больше 9 знаков).
